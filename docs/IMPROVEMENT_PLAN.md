# Improvement series acceptance criteria

The series targets the existing FDR workflows, without changing the landing artwork or replacing sign-up motion.

- Reusable record, document, money and search calculations must be deterministic.
- Backend changes must preserve institution isolation and separation of duties.
- New register controls must keep exports consistent with filters.
- Tests must exercise rejected and successful operations.
- Developer tools must not print credentials or deploy resources implicitly.
- All 100 commits must contain a substantive change in addition to the numbered change log.
- Production Firebase activation remains dependent on the owner’s project configuration.
